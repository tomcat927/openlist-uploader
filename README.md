# Openlist 上传管理器

基于 Tauri + React 的 OpenList 网盘上传管理工具，支持队列管理、定时上传、限速、热更新、系统通知等功能。

## 下载安装

从 GitHub Releases 下载最新安装包：

**https://github.com/tomcat927/openlist-uploader/releases/latest**

下载 `.exe` 安装包，双击安装即可。

### 在线热更新

软件内置自动更新功能：

- **启动时自动检查更新**（设置页可关闭，默认开启）
- 发现新版本弹出对话框，确认后自动下载安装并重启
- 热更新直连 GitHub 加速代理，不走系统代理，不受 Clash 等代理工具影响

## 功能特性

### 上传管理
- **队列管理**：添加、删除、清空上传队列，拖拽添加文件/文件夹
- **重复检测**：相同文件+相同目标路径不会重复添加（详见下方说明）
- **持久化存储**：程序重启后队列和历史记录不丢失
- **失败重试**：自动重试机制，可配置重试次数
- **历史记录**：按时间排序（升序/降序）、按文件名搜索、按状态筛选（全部/成功/失败）
- **大文件保护**：115 网盘非会员 5GB 文件拦截、4GB 文件风险提示
- **打开文件所在目录**：队列、历史记录、拦截记录均支持定位本地文件

### 上传配置
- **并发数**：同时上传的任务数量（默认 1）
- **最大重试次数**：失败后自动重试次数（默认 5）
- **As-Task 模式**：使用 Alist 后台任务功能（默认启用）
- **上传限速**：通过 AList admin API 控制服务端→云盘上传速度（0 = 不限速）
- **每轮任务数上限**：达到上限后本轮自动停止（0 = 不限）
- **显示进度**：状态列显示上传百分比
- **同名文件策略**：云端已存在同名文件时的处理方式（详见下方说明）
- **拦截重复添加**：同一文件重复添加到队列时拦截（可配置是否拦截不同目标路径）

### 定时上传
- 设置开始时间和结束时间
- 到达开始时间自动从队列取任务上传，无需手动点「开始上传」
- 到达结束时间等待当前任务完成后自动停止
- 支持定时上传开始/结束时发送飞书通知

### Alist 进程管理
- **自动启动 Alist**：设置页填写 Alist 可执行文件路径，打开本软件时自动启动
- **后台启动**：隐藏控制台窗口（默认开启）
- **退出时关闭 Alist**：退出本软件时同时关闭 Alist 进程（默认开启）
- **测试启动按钮**：设置页可手动测试启动 Alist，轮询 30 秒检测就绪状态

### 代理配置
- **使用系统代理**：默认关闭，本地 Alist 不需要代理
- 远程 Alist 服务器可开启系统代理
- **热更新不走系统代理**：直连 GitHub 加速代理，不受 Clash 干扰

### 通知
- **上传完成通知**：任务完成/失败时发送 Windows 系统通知（设置页可开关）
- **失败飞书通知**：上传失败超过重试阈值时发送飞书 Webhook 通知
- **队列完成飞书通知**：整个队列自然完成时发送飞书通知
- **测试通知按钮**：设置页可测试飞书 Webhook 配置是否正确

### 完成后关机
- **上传完成后关闭电脑**：队列自然完成后自动定时关机（默认延迟 10 分钟）
- 支持自定义延迟分钟数
- 关机前弹窗倒计时，可取消

### 系统托盘
- 最小化到托盘，关闭窗口默认最小化（设置页可配置）
- 托盘图标右键菜单：显示窗口、退出
- 点击托盘图标恢复窗口

## 使用说明

### 基本流程

1. **安装并打开软件**
2. **配置 Alist**（设置页）：
   - 填写 Alist 服务地址（默认 `http://127.0.0.1:5244`）
   - 填写用户名和密码
   - 点击「登录获取 Token」
   - 如需自动启动 Alist，填写 Alist 可执行文件路径
3. **选择目标目录**：在待上传队列页选择 Alist 中的目标目录
4. **添加文件**：点击「选择文件」或拖拽文件到窗口
5. **开始上传**：点击「开始上传」按钮

### 定时上传

1. 设置页 → 启用定时上传
2. 设置开始时间（如 `03:00`）和结束时间（如 `07:00`）
3. 把文件添加到待上传队列
4. 到达开始时间会自动开始上传，无需手动点击
5. 到达结束时间会等待当前任务完成后停止

### 上传限速

1. 设置页 → 上传限速选择速度（0/1/2/5/10 MB/s 或自定义）
2. 限速通过 AList admin API 控制 AList→云盘的上传速度
3. 需要 Alist 管理员权限

### 同名文件策略

设置页 → 同名文件策略，两个选项：

**跳过（默认）**

- 上传时发 `Overwrite: false` 头给 OpenList
- OpenList 按文件名检查云端是否已有同名文件，有则直接返回 403 不传输
- 软件收到 403 后将任务标记为完成，不实际上传文件
- **优点**：不浪费带宽，已有文件秒完成
- **缺点**：同名但内容不同（如版本更新）也会被跳过，旧文件不会被覆盖

**覆盖**

- 上传时发 `Overwrite: true` 头 + `X-File-Sha1` 头（全文件 SHA1 哈希值）
- OpenList 跳过文件名检查，进入存储驱动层（如 115 网盘驱动）
- 115 驱动用 SHA1 + 文件大小向 115 服务器发起秒传请求：
  - **相同内容**（SHA1 一致）：115 服务器直接创建文件引用，不实际传输数据，秒级完成
  - **不同内容**（SHA1 不一致）：正常上传，覆盖云端旧文件
- **优点**：相同内容秒传不浪费带宽，不同内容自动覆盖
- **缺点**：覆盖模式下上传前需计算全文件 SHA1，大文件会有短暂的哈希计算等待（通常几秒到几十秒，取决于磁盘速度）

#### 原理链路

```
客户端                          OpenList (fsup.go)              115 驱动 (driver.go)
  │                                 │                              │
  │  Overwrite: false               │                              │
  ├────────────────────────────────>│ fs.Get() 按文件名检查         │
  │                                 │ 同名 → 403 "file exists"     │
  │<────────────────────────────────│                              │
  │ 标记完成（不传文件）            │                              │
  │                                 │                              │
  │  Overwrite: true                │                              │
  │  X-File-Sha1: <hash>            │                              │
  ├────────────────────────────────>│ 跳过文件名检查                │
  │                                 ├─────────────────────────────>│ rapidUpload(size, sha1)
  │                                 │                              │ 问 115 服务器是否有相同 SHA1
  │                                 │                              │
  │                                 │  │  相同 → 秒传完成           │
  │                                 │  │  不同 → 正常上传覆盖       │
  │                                 │<─────────────────────────────┤
  │<────────────────────────────────│                              │
```

#### 选择建议

| 场景 | 推荐策略 | 原因 |
|---|---|---|
| 日常上传新文件 | 跳过 | 避免误覆盖，相同文件名不重复传 |
| 更新已有文件内容 | 覆盖 | 确保云端是最新版本，相同内容秒传 |
| 批量重传同一目录 | 覆盖 | 利用秒传，已存在的文件秒级完成 |
| 不确定云端文件状态 | 跳过 | 保守策略，不覆盖任何已有文件 |

### 重复添加检测

添加文件/文件夹到待上传队列时，软件会检查队列中是否已有相同文件，避免重复入队。检测规则取决于设置页的「拦截同一文件重复添加」开关：

**开关关闭时（默认）**

- 判断条件：**文件路径 + 目标路径** 都相同才拦截
- 同一文件夹重复添加到**相同**目标路径 → 拦截，提示"文件已在队列中，已跳过"
- 同一文件夹添加到**不同**目标路径 → **不拦截，正常入队**（因为传到不同目录是合理场景，如同一份资料传到两个网盘路径）

**开关开启时**

- 判断条件：只看**文件路径**，不看目标路径
- 同一文件夹无论添加到哪个目标路径 → 都拦截，提示"文件已在队列中（可能目标路径不同），已跳过"

#### 注意事项

- 检测仅针对队列中 **Pending（待上传）** 状态的任务。如果文件已开始上传或已完成，第二次添加同一文件**不会被拦截**，会重新入队
- 文件夹添加时会递归收集内部所有文件，逐个进行重复检测

### 拦截记录处理

被拦截的文件不会丢失，会记录在「拦截记录」页，每条记录按拦截原因提供对应的处理按钮：

| 拦截原因 | 文件大小 | 显示按钮 |
|---|---|---|
| 文件名/目录名超过 175 字节（115Crypt 加密驱动限制） | 任意 | **改名重传** |
| 单文件超过 5GB（115 网盘非会员限制） | >5GB | **分卷压缩** |
| 名称过长 + 超过 5GB | >5GB | **分卷压缩** |

**按钮行为**

- **改名重传**：自动截断名称到 175 字节内。单文件会包装为「短名-dir」文件夹，文件夹内包含短名文件和「原名.txt」存根；分卷文件夹会同时截断文件夹名和内部 `.partN.rar` 分卷名并生成存根。处理后自动按原目标路径重新入队
- **分卷压缩**：调用 WinRAR 分卷压缩为小于 5GB 的卷，压缩过程中若产物名称超长会**自动改名**（文件夹名和分卷名都会检查），完成后自动入队

**名称和大小同时超限时，优先分卷压缩**

分卷压缩一次解决两个问题（压缩时自动改名 + 分卷后单卷小于 5GB），因此这类记录只显示「分卷压缩」。避免先改名重传后再次被 5GB 限制拦截。

**其他操作**

- **标记已处理**：已自行处理完的记录手动标记，不再显示操作按钮
- **删除**：移除该条记录（不影响本地文件）
- **定位**：打开被拦截文件所在的本地目录

### 自动启动 Alist

1. 设置页 → 填写 Alist 路径（如 `E:\system_software\alist\openlist.exe`）
2. 勾选「后台启动 Alist」（隐藏控制台窗口）
3. 勾选「退出时关闭 Alist」
4. 保存配置
5. 可点击「测试启动 Alist」验证路径和启动是否正常
6. 下次打开软件会自动启动 Alist 并等待就绪后自动登录

## 技术栈

- **前端**：React 19 + TypeScript + Vite
- **状态管理**：Zustand
- **桌面框架**：Tauri 2.x
- **后端**：Rust
- **HTTP 客户端**：reqwest

## 数据存储

- **Windows**：`%APPDATA%\openlist-uploader\`（从旧版 `alist-uploader` 升级时自动迁移数据）
- 存储文件：`queue.json`（队列）、`history.json`（历史）、`config.json`（配置）、`blocked_files.json`（拦截记录）

# 安装依赖
